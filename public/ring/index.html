Open-source force-sensitive exercise controller

把形变，变成游戏语言。

OpenRing 不是复刻一个外壳，而是探索一套开放的力感运动控制器：弹性结构提供阻力，传感器读取压与拉，摄像头和 IMU 补齐姿态与运动，最终输出可供游戏理解的“语义动作”。

工程判断：可行。 最大不确定性不在“能否读到形变”，而在打印结构能否长期、稳定地回弹与复现同一读数。

01 / sensing paths

先证明可玩，
再追求测力。

三条路线分别回答三个问题：能否快速得到连续输入、能否把微小位移放大成干净信号、能否最终测出更稳定的真实结构应变。不要在第一版同时攻克全部问题。

V0 · 最快原型

线性 Hall / 距离

磁铁与 SS49E、DRV5055 或 A1324/25/26 的间距变化，映射为连续模拟电压。

  • 机械简单、无接触
  • ESP32 ADC 可直接读取
  • 预留约 5–25 mm 可调位
V1 · 机械放大

磁角度 / AS5600

用连杆或柔性铰链把数毫米形变变成明显的磁铁旋转，再读取绝对角度。

  • 数字 I²C 输出
  • 适合 3D 打印机构
  • 比直接贴应变片更易调试
V2 · 最终测力

应变片 / 电桥

把形变集中到测量梁，由应变片、电桥与高增益 24-bit ADC 读取微小阻值变化。

  • NAU7802 优先，HX711 易入门
  • 半桥/全桥利于灵敏度与温漂
  • 贴片位置比 ADC 型号更关键
传感路线对照——测到的物理量不同，最终都需通过标定映射为 compression / force。

型号避坑：A3144 是开关型 Hall，适合判断“到 / 没到”，不适合连续形变；商品标注含混的“44E”也应先确认是 linear / analog output。若只买一个起步型号，选 SS49E。

02 / build it

一张能开工的
BOM 与清单。

先打印 100–150 mm 弧形试件，而不是完整圆环。把“压约 5 mm → 连续、可复现的信号”跑通，剩下的才主要是机械设计问题。

最快 PoC / Hall 路线

  • ×1ESP32采样、滤波与 BLE；已有即可
  • ×1SS49E 或 DRV5055必须是线性模拟 Hall，不是 A3144 开关
  • ×1小型钕磁铁来源建议尺寸为 5×3 mm 或 6×3 mm
  • ×1弧形试件 + 可调滑槽PETG / PA / 玻纤尼龙，留出距离调节

应变升级补充

  • ×2/4BX120-3AA 120Ω 应变片半桥或全桥；单片四分之一桥需补精密桥臂
  • ×1NAU7802 或 HX711 模块现成模块优先；ADS1232 裸 IC 还需外围电路与 PCB
  • 若干120Ω / 0.1% 低温漂电阻四分之一桥或半桥需要；约 10–25 ppm/°C
  • ×1应变片专用胶胶层应薄且硬，先打磨、清洁与脱脂

台架验证 / Done 才进入整环

  1. 集中形变设计局部 sensing beam；不要把应变片随意贴在整个 PETG 圆环上。
  2. 找工作点移动磁铁，避开过近导致的 Hall 饱和区，确保全行程读数都有变化。
  3. 采 neutral 与极值记录中性、轻压、中压、重压与松手回零；分别考虑 push / pull。
  4. 检查复现与漂移重复压放，观察同一位置是否得到近似读数，并关注打印方向、温度与材料 creep。
  5. 做滤波与标定将 raw ADC 转为 −1.0…+1.0，再计算 velocity、rep count 与 hold time。
  6. 最后再做完整环若追求稳定，Ring 可打印，测量梁改用薄弹簧钢或铝片。

材料边界：PLA 不适合高频反复大形变；PETG 更适合验证，但层纹、填充、打印方向、温度和蠕变都会削弱“力 ↔ 读数”的长期稳定性。

03 / signal pipeline

从微小变化，
到开放协议。

硬件不必一开始输出牛顿。游戏首先需要的是方向一致、零点稳定、跨用户可标定的连续值；绝对力值需要额外的机械与砝码标定。

02 / SENSORHall / Gauge间距、角度或微应变转为电信号
03 / FRONT ENDADC + PGAESP32 ADC，或 NAU7802 / HX711 / ADS1232
04 / FIRMWARE滤波 + 标定零点、正负极值、曲线与重复动作特征

04 / open-source map

软件已有路，
开放硬件仍缺环。

现有作品的成熟方向主要是读取原版 Ring-Con、把力值映射到 PC 输入或虚拟场景；“STL + BOM + 应变检测 + ESP32 固件”的完整 DIY 方案仍未形成公认范本。

可借鉴的软件生态

  • Ringcon-Driver　读取原版传感值、校准 push / pull，并映射为 PC / X360 控制输入。
  • WebHID experiments　在浏览器读取连续 force sensor value，适合参考兼容层与归一化模型。
  • SuperLouis64 mods　把原版设备接入其他游戏，证明“力感运动控制器 → 通用游戏输入”的空间。
  • osc-ringcon　通过 Bluetooth / OSC 把连续 flex 参数接入 VRChat。

THE GAP

OpenRing 可补上的一段

社区常见链路是“原版 Ring-Con → 逆向协议 → PC driver / game mods”。OpenRing 要补齐的是另一端：

3D printed ring
↓
strain gauge / Hall
↓
ESP32 + open protocol
↓
games & tools

最值得复用的是已有的数据模型与软件接口，而不是机械外形；传感结构与协议可以做得更开放。

05 / multimodal architecture

不是三种控制器，
是一个动作。

摄像头判断“身体做了什么”，Ring 识别“用了多少力”，IMU 捕捉朝向与加速度。产品层不应把它们分别交给游戏，而应融合为开发者可以直接消费的语义事件。

CAMERA / POSE

动作质量

  • 深蹲深度与躯干倾角
  • 手臂位置与身体旋转
  • 平衡、节奏与对称性
RING / FORCE

发力质量

  • squeeze / pull force
  • 力度变化速度
  • 保持时长与稳定性
IMU / MOTION

空间运动

  • 环的朝向
  • 加速度与释放动作
  • 瞄准与手腕旋转

DEVELOPER RULE

把技术复杂度留在平台层

游戏开发者定义“深蹲深度 > 0.8 + 躯干倾角 < 15° + 压力 0.4–0.7 + 保持 > 800 ms”，不必直接处理姿态识别、应变片或 ESP32 数据。

06 / game concepts

让力成为玩法，
不是计数器。

连续输入的价值不只在“更大力”。力度的速度、稳定性、甜区与衰减，都可以变成技能、风险、合作与动态难度。

01 / 推荐首个 Demo

魔法战斗

姿势决定法术，Ring 压力决定蓄能，身体转向与环朝向负责瞄准，真实前推动作完成释放。30 秒内即可解释多模态价值。

02

动作 RPG

深蹲深度、侧闪和 stance 决定动作是否成立；同时保持目标压力可触发 perfect attack，而不是机械重复固定次数。

03

射箭 / 技能

拉力模拟 draw strength，摄像头看肩线与手臂，IMU 负责瞄准。长弓、短弓与魔法弓对应不同的力度—时间曲线。

04

潜行 / 拆弹 / 解谜

稳定保持 32–38% 的力度甜区，或在转体时寻找保险箱反馈。轻与稳比“最大力”更重要。

05

双人协作

一人控制引擎压力、一人用姿态转向；或两人把归一化力值维持在 ±5% 内，让不同力量水平也能公平合作。

06

自适应教练

当动作仍标准但输出力与速度下降时，下一关从最大力挑战转为精准控制；根据疲劳与技能调整玩法，而非只发奖励。

07 / staged MVP

四步走到
可玩的系统。

每一阶段只增加一个主要未知量：先有稳定信号，再有开放输入，再加空间动作，最后才融合视觉语义。

M0 / BENCH

弧段与信号

Hall + magnet + ESP32；压放 5 mm，验证连续性、回零与重复性。

M1 / RING

整环与协议

输出 force −1…+1、velocity、rep_count 与 hold_time，经 BLE 或网页接入。

M2 / MOTION

加入 IMU

把朝向、加速度与力组合，完成无需摄像头的蓄力—瞄准—释放 Demo。

M3 / VISION

语义动作 Demo

摄像头姿态 + Ring + IMU 融合，优先做“魔法战斗”而不是完整 RPG。
